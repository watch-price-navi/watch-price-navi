## 1. これは何か

腕時計の価格比較サイト。楽天市場・Yahoo!ショッピングの出品価格を毎日自動収集し、
型番ごとに最安値を並べる。全自動で運用し、アフィリエイトと買取リードで収益を得る。

- 公開URL: https://watch-price-navi.github.io/watch-price-navi/
- リポジトリ: https://github.com/watch-price-navi/watch-price-navi （**Public**。秘密情報を絶対に置かない）
- 掲載: 39ブランド / 29,269モデル（人手968 + 自動28,301）
- 構成: Next.js 15 App Router / `output: 'export'` の静的書き出し / GitHub Pages

## 2. 自動運用（触らなくても毎日動く）

GitHub Actions `.github/workflows/update-prices.yml` が1日2回動く。

| 時刻(JST) | 内容 |
|---|---|
| **6:20** | 記事1本生成 → Instagram投稿画像作成 → 価格収集 → 新作検出 → サイト公開 → **Instagram投稿** |
| **18:20** | 価格収集 → サイト公開（記事生成・Instagram投稿はしない） |

所要は2〜3時間。**毎時0分はGitHub側が混雑して最大50分遅れる**ため20分にずらしてある。

### 設計上、絶対に壊してはいけない約束

- `concurrency.cancel-in-progress: false` … 進行中の実行を止めない。
  以前 true にしていて、価格収集の最中にpushして収集ごと打ち切る事故を3回起こした。
- **価格データが無いビルドは公開しない**（`Check price data before deploying`）。
  push実行は収集を飛ばすので、そのまま公開すると中身の無いサイトが良い版を上書きする。
- 夕方の回を判定する `github.event.schedule != '20 9 * * *'` が**8箇所**ある。
  cronを変えるときは全部揃えること。揃え忘れると夕方にも記事生成とInstagram投稿が走る。

## 3. 収益の構造（配置を考えるときの前提）

| 経路 | 1件あたり | 状態 |
|---|---|---|
| **買取リード（みんなの買取）** | **7,500〜10,000円** | 稼働中 |
| eBay (EPN) | 4%・上限$550 | 稼働中 |
| 楽天 | 2%・**1商品1,000円上限** | 稼働中 |
| Yahoo! (バリューコマース) | 約1% | 稼働中 |
| 米田屋（もしも） | 要確認 | 稼働中 |
| AdSense | 微額 | 稼働中 |

**買取が楽天の約10倍**。しかも購入という重い決断が要らずフォーム入力だけで成立する。
だから買取導線を最優先で配置している（ヘッダー「時計を売る」／`/sell/`／出品の無いページでは最上部）。

eBayは単価が大きいが**成果の有効期間が24時間**しかなく、最終クリック方式。
契約は**0日前通知で変更・解除できる**ので、収益の柱にしてはいけない。

## 4. 規約の制約（これを破るとサイトが死ぬ）

### 楽天ウェブサービス規約 第8条4項 ← 最重要

> ウェブサービスを使用した部分において、楽天のサイト以外へのリンクを設けてはならない

**楽天から取得した写真・価格を表示している領域からは、楽天以外へリンクできない。**
違反すればAPI利用停止＝価格も写真も取れなくなり、サイトの中身が全部消える。

### 写真をどこから増やすか（2026-08-16 調査）

| 手段 | 実測 | 使えるか |
|---|---|---|
| **楽天の2枚目・3枚目** | 5件で14枚（1枚目だけなら5枚）＝**2.8倍** | **サイトで使える。実装済み** |
| 走査を深くする | 出品のあるモデル自体が増える | 実装済み |
| eBay の出品写真 | 1出品に複数枚。任意のモデルで角度が揃う | **承認待ち。本命** |
| CC画像（Openverse＝Flickr＋Wikimedia） | 型番では0件。モデル名なら数件〜24件 | 有名モデルのみ |
| Amazon アソシエイト PA-API | 商品画像の利用が明示的に許諾されている | 要審査＋180日で3件の売上 |
| メーカー公式・Chrono24 | — | **不可**（著作権・規約） |
| AI生成 | — | **不可**（実在しない個体を売り物の隣に置くことになる） |

**楽天の写真は Instagram に使えない**（規約 第10条）。サイトとInstagramで使える写真源が違うことを常に意識すること。

CC画像は Openverse の API（鍵不要だが回数制限あり）で引ける。
型番（`126610LN` など）では引けず、モデル名（`Omega Speedmaster Professional`）で引く。
実際にスピードマスターでは 裏蓋・クラスプ・真横・ムーブメント が揃った。
網羅率を正確に測るには無料の API キーが要る（無鍵だと数十回で制限に当たる）。

## 8. 過去に踏んだ地雷（同じ失敗を繰り返さないために）

1. **`cancel-in-progress: true`** … 価格収集を3回打ち切り、写真が2日間消えた。
2. **価格の無いビルドを公開** … 中身の無いサイトが良い版を上書きした。→ 関門を追加済み。
3. **ベルトが本体として最安値になる** … 下限を出品自体の中央値から計算していたため、
   ベルトばかりの型番では下限も下がって素通りしていた。→ `data/brand-min-price.json` を併用。
4. **ブルガリ ソロテンポを消しかけた** … `ST29S` をムーブメント記号と誤判定。
   シーガルの `ST1901` はST+4桁、ブルガリはST+2桁+英字。桁数で区別する。
5. **価格でモデルごと消そうとした** … 2,354件が対象になり、中に本物の型番が含まれていた。
   安いのは出品がベルトだからで、型番自体は実在する。**消すのはモデルではなく出品**。
6. **cronだけ変えて条件式を放置** … 夕方にも記事生成とInstagram投稿が走るところだった。
7. **正規表現の記号を外し忘れ** … `A. Lange` の `.` が任意の1文字として働き、
   19世紀の医学書のPDFを大量に拾った。
8. **Wikimediaの画像をファイル名だけで判定** … 店舗の建物・コンセプトカー・偽造品を拾った。
   → Commonsの**カテゴリ**で「時計である」ことを確かめる。
9. **優先順位をブランドの中だけで上げた** … 外側のブランドの並びが変わらないので
   後ろのブランドは丸ごと時間切れで飛ぶ。優先はブランドをまたいで効かせること。
10. **投稿が失敗しても緑だった** … ステップに `continue-on-error` が付き、さらに
    リトライのループが `echo` で終わるため終了状態が常に0だった。二重に隠れていた。
    → どちらも外し、失敗したら赤くする。**握りつぶす指定は、握りつぶしてよい理由を書けるときだけ使う。**
11. **記事生成は日本時間、Instagramの2本はUTCだった** … 朝6:20はUTCではまだ前日。
    その日作った記事ではなく前日の記事を投稿しようとしていた。日付は日本時間に統一する。
12. **投稿画像がサイトに出ていないのに投稿しようとした** … Instagramは公開URLから
    画像を取得するため404だと必ず失敗する。push実行は価格データが無く公開されないので、
    push実行で作った画像はサイトに出ない。朝の定期実行なら
    画像作成→公開→投稿が同じ実行の中で順に進むので起きない。
13. **ヘッダーが幅に収まらず全ページで横スクロール** … 2回起こしている。
    1回目はナビを2段目に折り返して収めたが、その2段目の中で今度は約55pxはみ出していた。
    `space-between` は余白が無ければ配りようがなく、間隔が0まで潰れて字が隣とくっつく。
    → スマホでは項目名を短くして幅そのものを詰め、`gap` で最低幅を保証する。
    → `body` に `overflow-x: clip` を置いた（`hidden` だと `sticky` が効かなくなる）。
    これは最後の砦であって、はみ出す原因そのものは必ず直すこと。
14. **申し送り書の追記が空振りしていた** … 文字列置換で追記していたが、
    対象が一致せず何も起きないまま「更新しました」と報告していた。
    → 追記したら `grep` で入ったことを必ず確かめる。
