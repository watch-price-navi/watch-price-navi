# セットアップ手順（この順番で進めれば公開まで完了します）

所要時間の目安: 約2〜3時間（各サービスの審査待ちを除く）。
**すべて無料**です。クレジットカードも不要です。

---

## STEP 0. 前提（完了済み）

- Node.js と Git はこのPCにインストール済みです。
- サイト本体・自動化スクリプトは実装済みです。

## STEP 1. GitHub アカウントとリポジトリ

1. https://github.com/ でアカウントを作成（無料）
2. 右上「+」→「New repository」
   - Repository name: `watch-price-navi`
   - **Public** を選択（Publicだと GitHub Actions の実行時間が無制限・無料）
   - 「Create repository」
   - 「Add a README file」は**チェックを外す**（既にファイルがあるPCから送るため。入れてしまった場合は下の注記を参照）
3. PowerShell でプロジェクトフォルダを開き、プッシュ:

```powershell
cd "C:\Users\uchida\Desktop\アフィリエイト用\watch-price-navi"
git remote add origin https://github.com/<あなたのユーザー名>/watch-price-navi.git
git push -u origin main
```

初回はブラウザが自動で開き、GitHubにサインインするだけで完了します
（Git for Windows 同梱の Git Credential Manager が処理します。パスワードやトークンの手入力は不要）。

> - GitHubの**パスワード認証は廃止済み**です。パスワードを入力してもエラーになります。上記のブラウザ認証を使ってください。
> - `rejected` と出たら、リポジトリ作成時にREADMEを入れたのが原因です。`git pull --rebase origin main` を一度実行してから再度 push してください。
> - コマンドが不安なら **GitHub Desktop**（GUI）でも同じことができます。
> - **ユーザー名は公開URLにそのまま出ます**（`https://ユーザー名.github.io/...`）。後から変えるとURLが変わり検索順位を失うので、最初に決めてください。

## STEP 2. GitHub Pages を有効化

1. リポジトリの Settings → Pages
2. 「Build and deployment」の Source を **GitHub Actions** に変更

これだけで、次回のワークフロー実行時に
`https://<ユーザー名>.github.io/watch-price-navi/` へ自動公開されます。

> **重要**: プロジェクトページ（上記URL形式）で公開する場合は、STEP 6 の
> `NEXT_PUBLIC_BASE_PATH` に `/watch-price-navi` を設定してください。
> 独自ドメイン（STEP 8）を使う場合は空のままにします。

## STEP 3. 楽天（アプリID + アクセスキー + アフィリエイトID）

> ### ⚠ 期限に注意
> 楽天の**旧APIは 2026年8月17日に完全廃止**されます（楽天ウェブサービス公式ブログ 2026-04-10 告知で確認済み）。
> 新しいAPIを使うには **アクセスキー** が必須です。これが無いと 8/17 以降は価格が1件も取れなくなります。
> **最優先でこのSTEP 3-1 を済ませてください。**

**審査はありません。楽天会員なら数分で発行できます。費用も無料・カード不要です。**

### 3-1. アプリを登録してアプリID・アクセスキーを得る

1. https://webservice.rakuten.co.jp/app/create を開く
   （未ログインなら楽天IDのログイン画面に飛ぶのでログイン。楽天会員でなければその画面から無料登録できます）
   ※ 画面が英語で出たら、ページ内の言語切替で「日本語」にすると読みやすくなります
2. 登録フォームの入力項目と推奨値:

   | 項目 | 入れる値 |
   |---|---|
   | アプリ名（Application name） | `時計価格ナビ` |
   | アプリURL（Application URL） | `https://<ユーザー名>.github.io/watch-price-navi/`（STEP 2 の公開URL。独自ドメイン取得済みならそのURL） |
   | アプリの種類（Application type） | ウェブサイト系を選択 |
   | **許可サイト（Allowed websites）** | `https://<ユーザー名>.github.io` ← **パスなし・末尾スラッシュなし**。`RAKUTEN_ORIGIN` と同じ文字列にします |
   | データ利用目的（Purpose of data usage） | 「腕時計の価格比較サイトで、楽天市場の商品価格を表示し楽天アフィリエイト経由で送客するため」 |
   | 想定QPS（Expected QPS） | `1`（レート制限は1リクエスト/秒） |

3. 登録後、アプリ一覧 https://webservice.rakuten.co.jp/app/list でアプリを開き、
   **アプリID（applicationId）** と **アクセスキー（accessKey）** の両方を控える

> - 1アカウントにつきアプリは**最大5個**まで登録できます。
> - 新エンドポイントは `https://openapi.rakuten.co.jp/ichibams/api/IchibaItem/Search/20260701` です（実装済み）。
> - `RAKUTEN_ORIGIN` は「許可サイト」と同じ値にしてください。403エラーが出たときはここの不一致が第一容疑です。

### 3-2. Origin ヘッダについて（重要）

新API基盤は、リクエストに **`Origin` ヘッダ**が付いていて、かつアプリ登録時の「許可サイト」のドメインと一致することを要求します。
本プロジェクトは Node から明示的にこのヘッダを送るため、環境変数 `RAKUTEN_ORIGIN` を設定してください。

`Origin` ヘッダは仕様上 **スキーム＋ドメイン（パスなし）** の形です。GitHub Pages のプロジェクトページなら:

```
RAKUTEN_ORIGIN=https://<ユーザー名>.github.io
```

（許可サイト欄には `https://<ユーザー名>.github.io/watch-price-navi/` のようにパス付きで入れて構いません。楽天側はドメインで照合します。）

ローカルで動かすときも `localhost` ではなくこの公開ドメインを入れます（ブラウザではなく Node が送るヘッダなので、実際にそのサイトから通信する必要はありません）。
未設定の場合は `NEXT_PUBLIC_SITE_URL` の値が使われます（GitHub Pages 運用ならこれがちょうどパスなしドメインになります）。

### 3-3. アフィリエイトID（価格取得だけなら不要・後回し可）

**「登録」の手続きはありません。** 公式FAQ（000001088）は「楽天会員登録（無料）をしている方であれば、
どなたでもご利用いただけます」とのみ記載しており、申込フォームも審査もありません。やることは2つです。

1. https://affiliate.rakuten.co.jp/user/sites でサイトURLを登録する
   （パートナー規約 第5条第1項でリンク掲載サイトの登録が求められています）
2. **アフィリエイトID**（`xxxxxxxx.yyyyyyyy.xxxxxxxx.zzzzzzzz` 形式）を控える
   → **STEP 3-1 と同じ https://webservice.rakuten.co.jp/app/list で確認できます**
   （楽天の公式APIドキュメントが affiliateId の取得先としてこのページを案内しています。
   アプリID・アクセスキーと並んで表示されるので、3-1 のときにまとめて控えるのが効率的です）

> - アフィリエイトIDは**1アカウントにつき1つ**で、登録した全アプリで共通です。
> - 未設定でも価格の取得・表示は動きます（成果報酬用URLが付かないだけ）。
> - **報酬の上限**: 楽天市場は1商品あたり1,000円、1ユーザーあたり月3,000円が上限です
>   （公式FAQで2026年8月時点も有効なことを確認済み）。高額時計でも1件1,000円までなので、
>   収益の主軸は将来的に「時計買取リード」に置く計画です（`docs/収益化ロードマップ.md`）。
> - 受け取りは**3,000円まで手続き不要**で楽天キャッシュに入ります。銀行振込へ切り替えられるのは
>   「直近3ヶ月の確定報酬が毎月3,001円以上」になってからで、別途審査があります。
> - `affiliateId` を指定すると、APIのレスポンスの `itemUrl` 自体が成果報酬つきURL（`affiliateUrl` と同じ）に
>   置き換わります。本プロジェクトはこれを利用しています。

## STEP 4. Yahoo!（Client ID）

**審査はありません。Yahoo! JAPAN ID があれば数分で発行できます。**

1. Yahoo! JAPAN ID を用意（未取得なら https://account.edit.yahoo.co.jp/registration で無料登録）
2. https://e.developer.yahoo.co.jp/register を開く
3. 登録フォーム
   - アプリケーションの種類: **サーバーサイド（サーバーサイドアプリケーション）**
   - 利用するAPI: **ショッピング**
   - アプリケーション名: `時計価格ナビ`
   - サイトURL: STEP 2 の公開URL
4. 発行された **Client ID（アプリケーションID）** を控える → これが `YAHOO_APP_ID`

> ショッピングAPIの利用に追加申請は不要です。レート制限は30リクエスト/分（実装済みのリミッタが自動で守ります）。

> Yahoo! 側は Origin ヘッダの要求はありません。`appid` をクエリに付けるだけで動きます。
> レート制限は **30リクエスト/分** です（実装済みのリミッタが自動で守ります）。

## STEP 5. バリューコマース（Yahoo!ショッピングのアフィリエイト）

**ここだけサイト審査があります。サイトを一度公開してから（STEP 6〜7の後で）申請してください。**

1. https://www.valuecommerce.ne.jp/affiliate/ →「今すぐ無料で会員登録してみる」で無料登録
   - 費用は無料・カード不要ですが、**報酬振込先の銀行口座**（支店名・口座番号・口座名義）の入力が必須です
   - サイト単位の目視審査があります
2. 承認後、管理画面で「Yahoo!ショッピング」プログラムと提携申請
3. 広告スペースの **sid**（サイトID）と Yahoo!ショッピング広告の **pid** を控える
4. 「ツール」→「LinkSwitch」を有効化し、タグ内の `vc_pid = "…"` の値を控える

> バリューコマース承認前でも、楽天だけで収益化は始められます。
> VC_SID / VC_PID / NEXT_PUBLIC_VC_PID は後から追加すればOKです。

## STEP 6. GitHub に鍵と設定を登録

リポジトリの Settings → Secrets and variables → Actions で登録します。

**Secrets タブ（秘密の値）:**

| Name | 値 |
|---|---|
| `RAKUTEN_APP_ID` | STEP 3 のアプリID |
| `RAKUTEN_ACCESS_KEY` | STEP 3 のアクセスキー |
| `RAKUTEN_AFFILIATE_ID` | STEP 3 のアフィリエイトID |
| `YAHOO_APP_ID` | STEP 4 の Client ID |
| `VC_SID` | STEP 5 の sid（後からでも可） |
| `VC_PID` | STEP 5 の pid（後からでも可） |
| `ANTHROPIC_API_KEY` | **任意**。設定するとブログ記事がAI執筆になり品質が大きく上がります（月30本で百数十円）。未設定でもテンプレート記事が毎朝自動生成されます |

**Variables タブ（公開されてよい設定値）:**

| Name | 値 |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | `https://<ユーザー名>.github.io`（独自ドメインならそのURL） |
| `NEXT_PUBLIC_BASE_PATH` | `/watch-price-navi`（独自ドメインなら登録しない） |
| `RAKUTEN_ORIGIN` | STEP 3-2 の Origin（`https://<ユーザー名>.github.io`）。`NEXT_PUBLIC_SITE_URL` と同じ値なら省略可 |
| `NEXT_PUBLIC_VC_PID` | STEP 5 の LinkSwitch vc_pid（後からでも可） |
| `NEXT_PUBLIC_ADSENSE_SLOT` | STEP 9 のAdSense広告ユニットID（数字のみ。承認後でOK） |
| `NEXT_PUBLIC_CONTACT_EMAIL` | お問い合わせ用メールアドレス |

## STEP 7. 初回実行

1. リポジトリの Actions タブ → 「Update prices & deploy」→「Run workflow」
2. 2〜3時間ほどで完了し、サイトが公開されます（669モデルの価格取得と出品走査に時間がかかります。2回目以降は差分中心で速くなります）
3. 以後は全自動で動きます:
   - **毎朝 JST 6:00**: ブログ1本生成 → 価格更新 → 新作検出 → 公開
   - **毎夕 JST 18:00**: 価格更新 → 公開

## STEP 8. 独自ドメイン（強く推奨・年1,000〜2,000円程度）

SEOとAdSense審査のため、独自ドメイン（例: `tokei-navi.com`）の取得を強く推奨します。

1. お名前.com / Cloudflare Registrar 等でドメイン取得
2. リポジトリ Settings → Pages → Custom domain に入力し、案内どおりDNS設定（CNAME）
3. `NEXT_PUBLIC_SITE_URL` を新ドメインに変更し、`NEXT_PUBLIC_BASE_PATH` を削除
4. Actions からワークフローを再実行

## STEP 9. Google AdSense（サイト公開・記事掲載後に申請）

1. https://www.google.com/adsense/ で申請（独自ドメイン推奨）
2. 承認されたら `NEXT_PUBLIC_ADSENSE_CLIENT` に `ca-pub-…` を Variables 登録
3. AdSense 管理画面で「自動広告」をONにすれば広告掲載開始

## STEP 10. 検索エンジン登録

1. https://search.google.com/search-console でサイトを登録し、`sitemap/0.xml` を送信
   （サイトマップは4万URLごとに `/sitemap/0.xml`, `/sitemap/1.xml`… と自動分割され、
   すべて robots.txt に自動記載されるため、増えた分は検索エンジンが自動で見つけます）
2. https://www.bing.com/webmasters でも同様に登録
