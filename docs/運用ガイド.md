# 運用ガイド

## 何が全自動で動くのか

一度セットアップすれば、以下が**無人で**実行されます（GitHub Actions）。

### 毎朝 JST 6:00（フル更新）

1. **ブログ記事を1本自動生成**して公開（`scripts/generate-blog.mjs`）
2. **出品の一括走査**（`scripts/build-auto-catalog.mjs`）— ブランドごとに楽天・Yahoo!の出品を価格帯別に走査し、
   人手カタログ（39ブランド・669モデル）の価格取得と、未収録型番の**自動カタログ生成**（1ブランド最大600モデル）を同時に行う
3. 一括走査で拾えなかったモデルを型番キーワードで個別補完（`scripts/fetch-prices.mjs`）
4. 部品・ベルト等の除外フィルタ → ショップごとに最安1件 → 安い順に整理
5. **新作モデルの自動検出**（`scripts/discover-models.mjs`）— カタログ未収録の型番を候補として記録
6. サイト全ページを再ビルド（最安値・検索インデックス・構造化データ・sitemap更新）
7. GitHub Pages へ公開

掲載モデル数は人手カタログ669 + 自動カタログ（実際に売られている型番が自動で増えていく）で、
運用が軌道に乗ると**数千モデル規模**になります。

### 毎夕 JST 18:00（価格のみ更新）

価格を再取得して再公開。**1日2回更新**により、価格の鮮度で競合を上回ります。

人手が必要なのは「新作モデルの承認・追記」だけです（任意・週1回5分程度）。

## ブログの自動生成について

`scripts/generate-blog.mjs` が毎朝1本の記事を作ります。動作は2モードあります。

| モード | 条件 | 品質 | コスト |
|---|---|---|---|
| **AI執筆** | Secrets に `ANTHROPIC_API_KEY` を設定 | 高（1600〜2200字の読み物） | 1記事 数円程度 |
| テンプレート | APIキーなし（既定） | 中（カタログ情報を構成した記事） | 無料 |

記事の主役モデルは日付から決定的に選ばれ、**一度主役にしたモデルは一巡するまで再登場しません**。
切り口も5種類（歴史/シーン/選び方/ブランド技術/比較）を順に巡回するため、内容が単調になりません。
生成された記事は保存前に検証され、カタログに存在しないモデルIDや壊れた内部リンクは自動で除去されます。

AI執筆を使う場合は https://console.anthropic.com/ でAPIキーを発行し、
リポジトリの Secrets に `ANTHROPIC_API_KEY` として登録してください（月30本で百数十円程度）。

## 新作モデルの自動検出

毎朝の実行で、各ブランド名の出品を検索し、カタログにない型番らしき文字列を抽出して
`data/pending-models.json` に候補として書き出します（出品件数が多い順）。

```jsonc
{
  "candidates": [
    { "brandId": "rolex", "reference": "126610LV", "listingCount": 8, "approxPriceJpy": 1980000 }
  ],
  "dismissed": []   // ← 不要な型番をここに追加すると次回から無視されます
}
```

このファイルを週1回ほど確認し、本物の新作があれば `data/brands/<brand>.json` に追記してください。
Claude Code に「pending-models.json の上位3件をカタログに追加して」と頼むのが最も簡単です。

## モデル・ブランドの追加方法

`data/brands/<ブランドid>.json` にモデルを1件追記するだけです。形式は既存モデルをコピーして編集してください。
翌日の自動更新から価格収集・ページ生成に自動で含まれます。

一番簡単な方法は Claude Code に頼むことです:

> 「ロレックスに エクスプローラーII 226570 を追加して」
> 「ブランド『チャペック』を10モデル分追加して」

追加後は `npm run validate` でデータ検証できます。

## 言語の追加方法（例: 中国語）

1. `lib/i18n.ts` の `LANGS` に `'zh'` を追加し、辞書の各キーに `zh:` の訳を追加
2. `data/brands/*.json` はそのまま使えます（name_ja/name_en を流用表示するなら
   ページ側で `lang === 'zh' ? name_en : ...` のようにフォールバック）
3. `public/index.html` のリダイレクト分岐に zh を追加

## データ構造

```
data/brands/<brand>.json   ブランド情報 + モデル一覧(型番・素材・防水・機能タグ等)
data/taxonomy.json         検索の区分定義(素材12種・ムーブメント7種・機能タグ27種・性別3種)
data/brands-auto/<brand>.json  出品走査から自動生成されたモデル(毎朝自動更新・人手カタログ優先で統合)
data/dealers.json          提携外の取扱店(検索URLテンプレート {q} に型番が入る)
data/blog/<date>-<slug>.json  ブログ記事(毎朝1本自動追加)
data/pending-models.json   新作モデル候補(自動検出・要確認)
data/prices/               自動生成(gitには保存しない。CI実行ごとにAPIから再取得)
public/search-index.json   検索ページ用インデックス(ビルド時自動生成)
```

## 検索機能で使える区分

`data/taxonomy.json` で定義。ここに項目を追加すれば検索ページのフィルタに自動で反映されます。

- **ケース素材**（12）: ステンレス / チタン / カーボン / セラミック / ブロンズ / YG / RG / WG / プラチナ / コンビ / 樹脂 / その他
- **ムーブメント**（7）: 自動巻き / 手巻き / クォーツ / ソーラー / スプリングドライブ / キネティック / 音叉式
- **機能・タイプ**（27）: ダイバーズ / クロノグラフ / GMT / ワールドタイマー / ドレス / パイロット / フィールド / スポーツ / ラグスポ / ムーンフェイズ / 永久カレンダー / 年次カレンダー / トゥールビヨン / ミニッツリピーター / パワーリザーブ / スモセコ / スケルトン / デイデイト / 軽量 / 電波 / GPS / デジタル / アナデジ / ミリタリー / レーシング / 復刻 / 限定
- **その他**: 価格帯7段階 / ケース径6段階 / 防水3段階 / 性別3種 / ブランド39

検索条件はURLに反映されます（例: `/ja/search/?tag=diver&material=titanium`）。
この形式でリンクを作れば、任意の絞り込み結果へ直接誘導できます（SEO・SNS共有に有効）。

## トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| Actionsが赤い(失敗) | ログを確認。`npm run validate` 失敗ならdata/brandsのJSON構文エラー。Secrets未設定なら価格スキップで成功するはずなのでSecrets名のタイプミスを疑う |
| 価格が全モデル「準備中」 | APIキー未設定 or 無効。Secretsの `RAKUTEN_APP_ID` / `RAKUTEN_ACCESS_KEY` / `YAHOO_APP_ID` を確認 |
| 特定モデルだけ価格なし | 検索キーワードにヒットする出品がない。`searchKeywordJa` を実際に楽天で検索して調整、または `priceFloorJpy` が高すぎないか確認 |
| 関係ない商品(ベルト等)が混ざる | `scripts/fetch-prices.mjs` の `NG_WORDS` に除外語を追加、または該当モデルの `priceFloorJpy` を引き上げ |
| HTTP 429 エラーが多発 | レート制限。`--delay 2000` を付けて実行間隔を広げる |
| 楽天APIがエラーになる(2026年8月以降) | 旧エンドポイント廃止。`RAKUTEN_ACCESS_KEY` を設定すれば新エンドポイントに自動切替 |
| リンクがアフィリエイトにならない | 楽天: `RAKUTEN_AFFILIATE_ID` 設定を確認。Yahoo!: `VC_SID`/`VC_PID`(API側) と `NEXT_PUBLIC_VC_PID`(LinkSwitch) を確認 |
